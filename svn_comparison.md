**1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?**
*   **Git:** Ветка — это просто указатель (файл размером 41 байт) на определенный коммит. Создание ветки не копирует файлы, а просто создает новую ссылку.
*   **SVN:** Ветка — это физическая копия всей структуры каталогов в репозитории (через `svn copy`). Это требует времени и места на сервере, поэтому создавать ветки «на каждый чих» там накладно.

**2. Можно ли в SVN сделать коммит без интернета? Почему?**
*   **Нет, нельзя.**
*   **Почему:** SVN — централизованная система. Коммит отправляется напрямую на центральный сервер. Без соединения с сервером ты не можешь зафиксировать изменения в истории. (В Git коммит делается локально, а отправка на сервер — отдельная операция `push`).

**3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?**
*   **Бинарные файлы (арт, дизайн):** SVN умеет блокировать файлы (file locking), чтобы два человека не перезаписали друг друга. В Git это работает плохо.
*   **Огромные монорепозитории с гигабайтами данных:** SVN позволяет скачать только нужную папку (sparse checkout) без выкачивания всей истории. Git (без специальных надстроек) тянет всю историю целиком.
*   **Простота для новичков:** Централизованная модель с одним сервером понятнее для команд, которые не хотят разбираться в распределенных схемах.
